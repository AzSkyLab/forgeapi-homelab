# Repository working instructions

- **Every new session:** read `docs/session-handoff.md`, `docs/agent-architecture.md`, and `docs/progress.md` before choosing work. Find the currently installed Ponytail skill (the verified cache path at this handoff is `/home/zerocool/.codex/plugins/cache/ponytail/ponytail/4.10.1/skills/ponytail/SKILL.md`; discover it again if that version moved) and apply Ponytail in full. Use Claude Opus 5.5 (`claude-opus-5-5`) for planning and final code review, and Claude Sonnet 5 (`claude-sonnet-5`) for coding/implementation when model routing is available. Give delegated coding work explicit file ownership, say other agents share the tree, and preserve their edits. Keep delegation context and handoffs scoped; pass planner findings to the coder and reviewer so agents do not reread the full history or repeat the same exploration. Disclose unavailable routing or skill access; do not imply it ran or that a global model default changed.
- **Deploying in the work environment?** Read `docs/work-deployment.md` first and follow it; do not set up local development there. (`docs/work-prompt.md` is the prompt that starts such a session.)
- The default runtime is the agent-first architecture replacement. Start with `docs/agent-architecture.md` and `docs/progress.md`. `docs/rewrite-plan.md` is historical; `app.legacy:app` retains the previous API for existing state. `docs/archive-go/` is reference only; do not revive its scope.
- **Keep it small.** Work on the next milestone only. Do not add anything from the plan's Parked list (retries, cancellation, idempotency, outbox, authz, OTel, Postgres, Docker) unless the engineer asks for it. The 2026-09-30 redesign explicitly authorizes the operation ledger, idempotent intents, exact-plan execution and optional Floci tests. Agents use HTTP/OpenAPI; do not add an MCP server. The engineer builds ahead on the home lab; work-Mac verification is tracked separately in `docs/progress.md`.
- Local start must need nothing but `uv`: no auth, Azure, Docker or credentials. Auth and Azure are opt-in settings added at their milestones.
- Commands: `uv sync`, `uv run pytest`, `uv run ruff check .`, `uv run uvicorn app.main:app --reload`. Add a test with each behavior. Do not substitute fake results for real infrastructure evidence.
- New operation activities must never automatically retry an apply, force-unlock state, or replan during execution. Saved-plan digest and operation state govern execution. All Temporal workflows must be deterministic; I/O (database, Terraform subprocess) belongs in activities. Terraform activities run once (no retries): a saved plan must not be applied twice.
- Credentials: no client secrets or static API keys. The only approved credentials are a short-lived certificate on the dedicated Entra app registration for local Terraform runs, and a run-time GitHub token (`gh auth token`, never stored) for private pattern repos; hosted, those become a managed identity and a GitHub App. It is replaced by the Container App's system-assigned managed identity when the API is hosted. Never commit tokens, certificates, tenant-specific config or Terraform state; never log raw tokens or auth errors.
- Placement: with `FORGEAPI_TENANTS_PATH` set, business units decide subscription, injected inputs, allowed patterns/regions/environments and ownership (`docs/tenancy.md`). Never expose subscription/account/project IDs or other units' deployments to callers; never let a caller set a platform-injected input. `tenants.yaml` is tenant-specific and gitignored. With `FORGEAPI_TENANTS_SOURCE=db` teams live in the database and only operators change them through `/admin/teams` (audited, If-Match, impact-checked); operators come only from `FORGEAPI_OPERATOR_GROUPS`, never from the database.
- Audit (`docs/audit.md`): every mutating endpoint must record `accepted` before dispatching and `refused` on refusal; never add a way to change or delete events; never put secrets or tokens in event detail.
- Outputs (`docs/outputs.md`): never store, return or log a sensitive output value; report its name in `withheld_outputs`. Secrets live in the pattern's own Key Vault and the API passes references. Do not add a reveal endpoint.
- Patterns: no Terraform in this repo except `examples/`. Patterns are root modules in their own git repos, registered in `patterns.yaml`, versioned by tag and pinned to a commit per deployment. Pattern changes go to the pattern repo plus a new tag, never into the API.
- **Home lab: never create, change or delete anything in real cloud (Azure, AWS, GCP)** (engineer rule, 2026-10-03). Prove features on the Floci emulators; real-cloud runs happen only after the transfer to the work environment (`docs/work-deployment.md`).
- Azure scope: only patterns in `patterns.yaml`, in the lab subscription, free or near-free resources. No paid compute or new pattern types without explicit approval. Live resources and their state are listed in `docs/progress.md`; do not delete them without being asked. `.local/data/` still holds local state for one older vault: never delete it.
- **Keep `docs/work-deployment.md` and `docs/work-prompt.md` current.** It is what the work environment is deployed from. Any change to settings, identities, storage, request fields, endpoints, pattern-repo requirements, verification or known limits updates that brief **in the same PR**, including its "Current as of" line.
- Update `docs/progress.md` with behavior, evidence and the next task. Do not commit or push without being asked.
